```bash

mkdir keys

cd ~/java/One-Click/authService/authService-be/keys

# 1. Generate PRIVATE key (MỚI)
openssl genpkey -algorithm RSA -out private.pem -pkeyopt rsa_keygen_bits:2048

# 2. Extract PUBLIC key
openssl rsa -in private.pem -pubout -out public.pem

# 3. Secure private
chmod 600 private.pem

# 4. Gitignore
echo "keys/private.pem" >> ../../.gitignore
```

> Public key có thể validate token được sign bằng private key nhờ nguyên lý bất đối xứng của thuật toán RSA trong RS256. Private.pem chứa cả private exponent (d) và public components (modulus n, public exponent e), còn public.pem chỉ chứa public components (n và e) – chúng là một cặp toán học liên kết chặt chẽ.

### Quy trình Sign Token
> Private key mã hóa (sign) hash SHA-256 của header.payload thành signature.
Chỉ private key mới tạo được signature này vì cần private exponent bí mật.
Token hoàn chỉnh: header.payload.signature được gửi đi.

### Quy trình Validate
> Public key tính lại hash SHA-256 của header.payload từ token nhận được.
Sau đó dùng public key "decrypt" signature để lấy hash gốc và so sánh.
Nếu khớp → token hợp lệ (chứng minh chỉ private key tương ứng mới sign được). Nếu không khớp → token bị giả mạo hoặc sai key.

### Tại sao khác nhau nhưng vẫn verify được
> Private key chứa đầy đủ thông tin toán học (bao gồm public part), nên public key trích xuất từ nó có thể "nghịch đảo" quá trình mã hóa RSA một chiều.
Đây là "bí mật" của RSA: sign bằng private → verify bằng public (không ngược lại được).
